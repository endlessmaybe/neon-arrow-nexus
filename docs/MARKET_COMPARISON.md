# 同类产品对照与本项目取舍

这份对照不是为了照搬某一个游戏的素材或界面，而是把当前常见的 **Tap Away / Arrow Escape** 类箭头解堵游戏拆成可验证的交互规律，再检查“霓虹箭域”从规则、箭体、难度到反馈是否像一个真正的同类成品。

## 1. 对照对象

- Google Play：**Tap Away: Arrow Puzzle Game**  
  https://play.google.com/store/apps/details?id=com.mahboob.tap_arrows_puzzle_games
- Google Play：**Tap Away: Tap Puzzle Game**  
  https://play.google.com/store/apps/details?id=com.arrows.escape.puzzle
- Google Play：**Arrow Puzzle: Tap Away**  
  https://play.google.com/store/apps/details?id=com.tactpeak.arrowpuzzle
- **Arrow Puzzle: Arrows Escape** 官方站  
  https://arrow-puzzle.com/
- Google Play：**Arrow Escape: Tap Away Puzzle**  
  https://play.google.com/store/apps/details?id=com.gadgames.arrowescape

这些产品的共同核心都很明确：**看方向 → 找前方完全畅通的箭 → 点击离场 → 解开下一批箭 → 清空棋盘**。同类产品之间主题、关卡数量、是否计时、是否加入道具会不同，但“方向一眼可读、阻挡关系清楚、顺序是主要谜题”基本一致。

## 2. 从头到尾逐项比较

| 环节 | 市面同类常见做法 | 霓虹箭域当前实现 | 本轮处理 |
| --- | --- | --- | --- |
| 入门规则 | 一次点击，一个方向；前方无阻挡才能离场 | 点击箭后沿箭头方向计算完整射线 | 保持一致，规则不额外绕弯 |
| 箭头识别 | 箭头大、线条粗、轮廓简单，方向比装饰重要 | 彩色箭体 + 白色高光 + 深色描边 | 保留霓虹主题，但把主体改成更完整的粗线轮廓，弱化“发光小图标”感 |
| 箭体长度 | 同一关里长短明显不同，短箭和长箭混排形成节奏 | 每根箭实际占 2–4 个格子 | 恢复真实随机长箭，视觉跨度约为 1 / 2 / 3 格，不再用单格内的小数长度模拟 |
| 折线形态 | 线箭类产品常用直线或少量 90° 转折，避免软曲线 | 长箭可直行，也可在尾部随机 90° 转折；末段与箭头方向一致 | 保留随机性，同时让方向判断始终清楚 |
| 密集度 | 前期稀疏，后期明显更密 | 18–22 / 27–32 / 38–42 | 第三关扩到 13×16，以容纳更多真实长箭和机制 |
| 可读性 | 密但不能糊成一团，箭与箭之间必须能区分 | 箭体占用真实格子 | 生成阶段禁止不同箭体共格，也禁止占用机制格，视觉和碰撞完全一致 |
| 解题顺序 | “先移走谁”是主要难点，有些产品强调唯一或接近唯一的顺序 | 三关都允许多个安全选择 | 不再强制唯一解，让玩家自己选择路线；完整解序只用于证明地图可通关 |
| 失败反馈 | 点到受阻箭通常会抖动、闪烁或扣生命 | 棋盘抖动 + 红色粒子 + 稳定度 -1 + 阻挡提示 | 已具备，不再堆更多提示层 |
| 帮助能力 | Hint / Undo 很常见 | H 提示、U 撤销、A 自动求解 | 保留；课程作业版另外提供 AI 求解作为扩展 |
| 过关反馈 | 清空棋盘、星级/奖励、下一关 | 1–3 星、得分、连击、三关进度 | 保持 |
| 节奏压力 | 很多同类默认无计时，也有计时变体 | 三关都有倒计时 | 作为本作的挑战层保留，不冒充所有同类的统一规则 |
| 额外机制 | 后期常加入传送、钥匙、特殊砖等变化 | 90° 折光、180° 反相、跃迁、量子超载 | 保留为作业创新点，不影响基础“看方向/清阻挡”主循环 |
| 关卡规模 | 商业产品通常数百到上千关 | 课程要求下严格只有 3 关 | 不为了模仿商业数量破坏作业边界；用三关承担明确的 Easy → Medium → Hard 梯度 |

## 3. 为什么恢复真实随机长箭

把箭体压缩在单个锚点格内虽然有利于维持超高密度和唯一解，但视觉上会变成一堆尺寸接近的小符号，也让“箭身”和真实碰撞范围脱节。既然第三关已经取消唯一解，就没有必要继续保留这个妥协。

现在每根箭直接拥有 2–4 个真实身体格。长度由生成器随机选择，尾部可以出现 90° 转折，整条线同时参与显示、点击和阻挡。这样玩家看到的“长箭”就是真正占据多格的长箭，而不是装饰出来的视觉长度。

## 4. 为什么真实占格更适合当前版本

真实占格后，显示线与规则实体天然一致：箭身经过哪个格，那个格就确实被该箭占用。生成器会提前排除其它箭体和机制格，因此不会出现“视觉上穿过去但规则上没挡住”的假象。取消唯一解后没有再靠固定答案链制造难度，而是把终极困难扩到 13×16、38–42 条，并叠加双跃迁和分阶段相位锁，在保留 2–4 格真实长箭的前提下提高读图负担。

## 5. 当前仍刻意保留的原创差异

霓虹配色、折光/反相/跃迁、量子能量、AI 自动求解、RUN 可复现随机生成，都不是为了复制某一款商业游戏。模仿的是成熟品类已经验证过的 **信息层级和交互语法**：方向要明确、长短要有节奏、路径要可读、错误要有反馈、难度要逐级增加；素材、主题和扩展机制仍保持本项目自己的实现。

## 6. 2026-09-16 二次市场调研与新增取舍

本轮在软件已经可玩的前提下，再次检查了仍在分发的 Arrow Escape / Tap Away 类产品，而不是只参考早期截图。重点看的不是素材，而是“成熟产品如何在不改核心点击规则的情况下增加可玩性和完成度”。新增参考包括：

- Daily Arrow Escape（Google Play）：检索其当前商店页与功能说明
- Tap Away: Arrow Puzzle Game（Google Play）：`https://play.google.com/store/apps/details?id=com.mahboob.tap_arrows_puzzle_games`

调研中反复出现的产品化方向包括：路线/格线辅助、Undo/Hint、连击和星级反馈、Daily / Challenge / Zen 等模式、主题皮肤、离线进度，以及 reduced motion / 高对比等可访问设置。结合本课程作业“完整流程严格只有三关”的硬约束，本轮没有机械地把这些功能全部塞进项目，而是做了下面的筛选：

| 同类产品思路 | 本项目取舍 | 原因 |
| --- | --- | --- |
| Hover / move feedback | **改为玩家自主判断** | 悬停只高亮；成功点击后箭体沿自身方向完整飞出窗口，提示需主动按 `H` 请求 |
| Reduced motion | **加入：低动态模式 `V`** | 降低持续装饰运动，同时保留颜色和文字状态；设置可持久化 |
| Undo / Hint | **只保留撤销** | 保留 `U` 撤销作为容错；删除 `H` 安全箭提示，避免界面直接给出“安全出口”式答案 |
| Combo / 星级 | **原本已有并保留** | 连击、积分和 1–3 星评价已经形成额外目标 |
| Offline / 本地进度 | **原本已有并加强** | 游戏离线运行；自动存档同时记录低动态和音效偏好 |
| Daily / Endless / Zen / Boss | **本轮不加入** | 会模糊“整局只有三关”的课程边界，也会把精力从三关质量转移到数量堆叠 |
| 主题皮肤商城 | **本轮不加入** | 对课程展示价值低，而且容易把视觉精力浪费在换皮而不是统一设计系统 |
| 排行榜 / 社交 / VS | **本轮不加入** | 需要额外服务端与账号体系，和当前单机作业的验证目标不匹配 |

## 7. 视觉基准的进一步收敛

同类商业产品普遍优先保证箭头方向和路径关系一眼可读，因此这次没有把“高级感”理解成继续叠更重的 Bloom。最终选择的是 **Cyberpunk HUD / Sci-Fi FUI + 低装饰层级**：深色底、细边线、少量青/紫/洋红状态光、明确的按压反馈和低频启动仪式。

具体落实为：启动同步序列缩短到约 1.15 秒；背景删除扫描线、光谱丝带、轨道圈和透视网格；按钮删除双层玻璃、内高光、角标和扫描标记；成功箭则改成“箭头先走、箭身沿原折线依次跟随拉直、再沿最终方向出屏并后段淡出”的空间反馈。悬停不显示 `CLEAR VECTOR / ROUTE BLOCKED` 或路径答案，`H` 安全箭扫描入口也已经删除；`V` 低动态模式会跳过启动效果、冻结装饰运动并降低粒子量。

这一轮仍坚持一个原则：**借鉴的是成熟品类的交互模式，不复制任何产品的素材、关卡、图标或界面排布。**
