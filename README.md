# 霓虹箭域 · Neon Arrow Nexus

> 2026 秋软件工程个人作业（第二次）——“利用 AIGC 完成‘一箭又一箭’小游戏”的扩展实现。

霓虹箭域不是对基础玩法只做换色，而是在“判断箭头前方路径、按正确顺序逐步消除”的核心规则上加入了折光门、棱镜充能、量子超载、连击计分和三关递进。项目使用原生 HTML / CSS / JavaScript 与 Canvas 2D，不依赖第三方运行时包，打开成本低，便于提交、演示和部署。

![霓虹箭域桌面首屏](docs/screenshots/01-home-desktop.png)

## 1. 游戏玩法

- 点击一条箭路，如果其箭头方向到边界的完整飞行路径没有其他箭阻挡，则该箭路成功离场。
- 如果路径被阻挡，会发生碰撞并损失 1 点“稳定度”，连击清零。
- 清空当前关卡全部箭路即可过关；稳定度耗尽或倒计时归零则失败。
- `H` 或右侧“扫描安全箭路”可以获得提示，每次扣除 120 分。
- `R` 可重新开始当前关卡。

## 2. 相比基础玩法的创新点

### 2.1 折光门

第二、三关加入折光门。箭的飞行射线进入光门后会顺时针或逆时针旋转 90°，所以玩家不能只看箭头附近是否空闲，而要判断完整折线路径。

### 2.2 棱镜充能

部分箭路带有棱镜标记。成功消除后会提供更高分数与额外量子能量，形成“先解哪条箭”的二次策略。

### 2.3 量子超载

连续正确消除可把能量积累至 100%。玩家主动启动超载后，下一次点击一条被阻挡的箭可以相位穿透，不损失稳定度。这为复杂局面提供了有限的主动破局手段。

### 2.4 动态连击

连续正确操作会提高连击倍率和单次得分，错误点击会立刻中断连击。这样把原本只有“能否通关”的玩法扩展成“路线判断 + 风险控制 + 分数优化”。

### 2.5 可验证的可解关卡生成

关卡不是简单随机塞箭。生成器采用“**反向构造**”：

1. 从空棋盘开始放置最后一个可离场箭路；
2. 继续加入更早应该被消除的箭路；
3. 每次加入前都用真实射线规则检查该箭在当前已放置箭路中是否存在清晰出口；
4. 最终把构造顺序反转，得到一条保证可完成的解序；
5. 自动测试会重新按这条顺序执行完整关卡，确保不会生成理论死局。

因此三关在固定种子下既可重复生成，又能由测试程序证明存在完整解。

## 3. 视觉与交互

- 深色宇宙背景 + 青 / 紫 / 洋红霓虹色系；
- Canvas 光晕箭路、动态星点、扫描线与粒子爆发；
- 折光门持续旋转并带有双层发光结构；
- HUD 实时显示关卡、积分、连击、倒计时和稳定度；
- 操作成功、碰撞、棱镜与超载分别有不同视觉/音效反馈；
- 支持桌面、平板和手机布局；
- 所有按钮使用 SVG 图标或文字，不使用 Emoji 充当结构图标；
- 支持键盘焦点和 `prefers-reduced-motion`。

## 5. 本地运行

环境要求：Node.js 20 及以上。

```bash
npm start
```

浏览器打开：

```text
http://127.0.0.1:4173
```

项目没有生产依赖，因此无需 `npm install`。

## 6. 自动检查

```bash
npm test
npm run check
```

`npm test` 会验证：

- 3 个关卡在同一种子下生成结果一致；
- 每关生成箭路数量达到预期；
- 每关都存在由生成器记录并再次验证的完整解序；
- 初始局面至少存在受阻箭路，保证有实际解谜选择；
- 解序第一步在真实碰撞规则下可安全离场。
